# 主题、语言与标准主录表导入

顶部太阳、月亮、电脑分别选择白色、黑色和跟随系统。ZH、EN、DE分别选择中文、英文和德文。选择保存在本机浏览器，刷新仍有效。语言只影响界面，原始业务内容、编号、CSV表头和文件名保持原值。

在“导入”中选择标准CSV，检查目标主录、记录数和前3条预览，再点击“导入正式库”或“导入演示库”。两套数据来源相互隔离。标准模板覆盖当前SQL的146张基础主录表，固定启用，管理页面没有停用按钮。

## 空缺与已有记录

- 只检查含具体数据的行；整行空白会跳过。空单元格、仅含空格的单元格、缺少的尾部单元格均算空缺。
- 有空缺时询问“检查到表信息不全，是否还要导入？”。选“否，取消导入”不写入业务数据；选“是，继续导入”后空缺保持NULL，不编造业务值或填零。
- 遇到相同记录编号时询问“是否要使用最新一次的数据？”。选“是，使用最新数据”，使用CSV中的非空值覆盖原值，CSV为空的地方保留原值。选“否，只补原空白项”，保留原有非空值，只补填NULL、空字符串或仅含空格的文本。原有数字0和文本“0”属于非空值。
- 编号留空会生成稳定记录编号。更新已有记录应填写原编号；改变一个没有编号的CSV文件会生成新编号。
- 同一次检查重复提交返回同一批结果。重新检查开启新的导入操作，允许再次导入同一文件并重新选择合并方式。

## 文件与校验

保留下载的“部门.主录表名.csv”文件名、原始字段名和列顺序。每批最多5000条，单文件最多16MB；支持UTF-8和GB18030，推荐模板原有UTF-8 BOM。表头有歧义时，用原文件名确定目标表。

检查阶段在事务内试写后回滚，不保存业务记录或约束调整。正式执行重新核对文件SHA256、检查记录所属来源和字段结构；业务写入、审计和必要的约束调整在同一事务提交，失败整批回滚。

用户已授权放宽空缺相关约束。新增记录存在已确认空缺时，仅按实际缺失字段移除非主键字段的NOT NULL；纯粹要求一组关联“必须且只能填一项”的检查，在整组缺失时改为“最多填一项”。调整前后定义和批次有独立记录。主键、唯一性、已填写关联的有效性、数值检查及已过账保护继续生效。先导入被引用的基础资料，再填写关联编号；未知关联可留空。

PostgreSQL批次审计保存文件SHA256、目标主录、源行号、合并选择、每行修改前后值和新增/更新/未变数量。本机检查历史保留检查结果、前3条预览和执行结果，不保存上传原文件。文件或列结构变化需重新检查。

接口及验收见[导入说明](IMPORT_INTERFACE.md)。新环境安装空缺支持使用 `bin/enable-csv-import.py`，安装前备份数据库。
