# 表格导入接口

在经营工作台右上角点击「↑ 导入」。本阶段提供格式检查、已登记类型目录、停用/恢复和检查记录。**业务数据导入尚未开放**，所有检查结果的 `can_execute` 都是 `false`。

## 使用

1. 在「检查文件」选择或拖入文件，一次最多 10 个，每个不超过 16 MB。
2. 已登记且启用的结构显示「已登记 · 可用于导入」。这表示格式符合登记规则，不表示内容已核定或已经入库。
3. 未登记或结构变化的文件显示「需要新增支持」，不会自动登记。损坏或无法读取的文件显示「无法检查」。
4. 在「表格类型」点击「停用此类型」，即将该类型从可导入目录移除。同类文件随即显示「已停用 · 不可导入」。「恢复此类型」可重新启用。此设置对整个工作空间生效。
5. 在「检查记录」查看文件名、SHA-256、格式版本和检查时间。可展开查看检查时状态。徽标依据当前设置显示，停用前的成功记录也会显示当前不可导入。改变登记规则后，旧记录要求重新检查。

类型启停和检查记录重启后保留。正式/演示的检查记录分开显示，表格类型设置共用。每页 20 条检查记录；类型变更展示最近 50 条。关闭窗口会停止继续处理尚未开始的批次文件，已开始的文件可能完成检查并留下记录。

## 初始登记目录

| 表格类型 | 已登记版本 | 验证样例 |
| --- | --- | --- |
| 平台销售订单 | XLSX，export 工作表，32 列与 29 列两个版本 | 3 |
| 企业网银流水 | XLSX，Sheet0 工作表，HISTORYDETAIL 标记，第 2 行表头 | 3 |
| 企业聚合结算流水 | XLSX，sheet1 工作表，14 列 | 9 |
| 支付宝账务明细 | CSV，第 5 行表头，12 列 | 9 |
| 支付宝账务汇总 | CSV，第 5 行表头，6 列 | 9 |
| 保证金流水 | CSV，第 1 行表头，12 列 | 2 |

样例来自用户指定的 `D:\projx\demo\easyerp-old2\finance` 和 `sales`。共检查 36 份文件，35 份属于上述格式。`finance\保证金流水2026\part_Q1.txt` 是说明文字，没有结构化流水表头，保持不支持，需要人工处理。原始样例不修改。

识别按容器、工作表名称/数量、表头所在行、完整列名及顺序和特定文件标记匹配。文件名、月份、账号和业务数值不作为许可依据。表头两侧空白及 BOM 可规范化，列顺序、增减列或额外工作表变化均需明确新增支持。空白列尾不参与表头比较；数据出现登记列范围之外的单元格会拒绝匹配。当前不执行金额、日期、业务唯一键、期间覆盖、订单拆行或账户对账的内容核定，也不执行公式、宏或外部链接。

XLSX 读取实际工作表 XML，不信任导出文件中可能错误的 `dimension` 元数据。CSV/TXT 支持 UTF-8（可含 BOM）和 GB18030；仅登记了逗号分隔的表格版本。XLS、XLSM 等容器需要另行增加支持。最多 20 张工作表、每张 100,000 行/256 列、2,000,000 单元格，工作簿 ZIP 展开上限 96 MB。文件仅在内存中读取，未保存上传原件或业务行。

## 接口约定

| 方法与路径 | 用途 |
| --- | --- |
| GET /api/import/meta | 目录、启停状态、版本、大小限制及本机会话令牌 |
| POST /api/import/check?mode=live\|demo&filename=... | 原始文件字节检查，Content-Type 为 application/octet-stream |
| POST /api/import/settings | JSON：type_id、enabled（布尔值）、version（整数） |
| GET /api/import/history?mode=...&offset=0 | 当前来源的分页检查记录，包含检查时/当前状态 |
| GET /api/import/events | 最近 50 次类型启停变更 |
| POST /api/import/execute | 预留执行接口，固定返回 HTTP 501，绝不写业务数据 |

所有 POST 必须携带 `X-EasyERP-Token`，只接受本机 Host/Origin。文件名只作展示，不接受服务器文件路径。状态变更使用版本比较；页面设置过期返回 409，不能覆盖其他页面的新设置。未知类型不能通过管理接口自助登记。识别失败是有记录的检查结果；缺少文件、超大、非法文件名或不支持的扩展名返回 4xx，不生成成功记录。

JSON 响应以 `status`（recognized/unknown/invalid）、`match`、`format_eligible`、`enabled_at_check`、`currently_enabled`、`requires_recheck` 和 `can_execute` 区分格式是否识别、是否启用和执行是否开放。检查不生成“已导入”业务记录。

## 保存与扩展

- 登记定义：`frontend/import_formats.json`。这是经过开发、检查和测试后交付的规则，页面没有自动学习/任意表头批准入口。
- 本地记录：`var/import-interface.sqlite3`，独立于 PostgreSQL 业务库。SQLite 事务保存启停版本、变更和检查元数据。需要备份时使用 SQLite 的备份接口或停止前端后复制此文件。
- 样例清单及校验值：`reports/import-sample-manifest.json`。检查记录只存文件名、哈希、大小、结构规则与状态等元数据，数据库未新增表或权限。
- 后续支持新格式：增加/修订显式规则、提高目录版本、补充正反例测试。若要真正写入数据，需另行实现业务映射、必填值/精度/时区校验、来源追踪、去重和事务，再开放执行接口；不能把本阶段格式匹配当成业务数据核定。
- 后续真正执行时，必须重新校验文件哈希、登记版本和当前启停状态。不能信任客户端旧结果或历史 `format_eligible`。

验收：`python tests/test_import_interface.py --url http://127.0.0.1:8092`。这会读取原始样例，在本地导入记录中留下演示来源检查记录，临时停用/恢复销售类型以验证效果，最终恢复测试前设置；不调用业务 SQL 写入。既有 `tests/test_frontend.py` 与 `tests/test_manual_entry.py` 继续覆盖原有查询与手工录入流程。
