# easyERP 本机经营工作台

easyERP 把财务、销售、采购与生产、研发、法务和分析的主录放在同一本机数据库中。业务事实只录一次，页面、核对和交付通过ID关联生成。未知资料保留空缺，不用0代替，也不把资金记录自动当作收入、成本或收货。

## 第一次使用

1. 在项目根目录双击 `dashboard.exe` 打开经营工作台；双击 `sqlview.exe` 打开SQL管理界面。依赖本机已有的Python、PostgreSQL和pgAdmin，并非独立安装包。
2. 确认页面当前是正式数据还是演示数据。正式库用于真实业务，演示库用于练习，两者分开。
3. 日常可以查询、追溯、导出、手工录入，或下载空白主录模板后填写CSV再导入。涉及业务核定的内容仍需有依据的人确认。

默认本机地址：工作台 `http://127.0.0.1:8092/`，SQL管理界面 `http://127.0.0.1:8093/`；数据库名称和端口以 `config.json` 为准。启动器会启动或复用本项目服务，关闭浏览器不会停止数据库。

## 把文件交给Agent导入

将XLSX、CSV或文本文档等原文件放入 [import/inbox](import/inbox/)。可按财务、销售、采购生产等目录分类；不知道归属时放 `unclassified` 或直接放inbox。保留原文件名，无需先自己调整成数据库表。

然后告诉Agent：**“处理 import/inbox，更新正式库，按前端导入规则确认空缺和已有记录。”**

Agent先盘点与保留来源，解释文件并整理字段和ID，再转成标准主录CSV，使用前端同一套服务检查、备份和入库。有空缺或相同编号时沿用本批已明确的选择，缺少选择时先展示检查结果再询问。仅放文件不会自动写库。

每批的来源副本、字段及源行对应、标准CSV、检查和入库回执保存在 `import/batches/`。一个工作簿可以部分完成；未能确定的字段或关联会列为待确认。详见[导入箱说明](import/README.md)和[文件导入流程](docs/import-workflow.md)。

## 项目文件怎么分

| 位置 | 保存内容 |
| --- | --- |
| `docs/` | 全局规则、导入流程和完整技术规范 |
| `import/inbox/` | 等待Agent处理的原文件 |
| `import/batches/` | 每次处理的来源、映射、检查和回执 |
| `frontend/` | 页面、查询、手工保存和共用导入服务 |
| `bin/` | 本机维护工具和导入箱入口 |
| `db/` | 基础SQL生成文件、附加实现和构建清单 |
| `launcher-src/`、`icons/` | Windows启动器和图标 |
| `tests/`、`reports/` | 测试及对应时间的验证证据 |
| `.secrets/`、`var/` | 本机私密配置、数据库集群和运行状态 |
| `backups/`、`exports/` | 数据库备份和导出；需另外妥善备份 |

业务输入、导入批次、凭据和运行数据不提交Git。源码、规则、目录说明和空目录标记可版本管理；Git忽略不等于备份。代理约定保存在本机 `AGENTS.md` 和 `.agents/skills/`。

## 维护时保留的边界

正式结构修改或入库前先备份，核对目标库与本项目集群。不要删除 `var/pgdata` 或重建正式库来消除错误；查询、写入、审计和已过账保护继续分工。

旧版根readme已原字节保存为 `docs/sql-specification.md`。构建工具从该文件提取基础SQL；SQL内已有的 `readme.md:行号` 是历史来源标记，现在对应技术规范中的同一行。此调整保持源规范和六个SQL文件哈希不变，不改变数据库业务结构，也无需重建数据库。

历史报告只证明当时执行过的检查。具体运行状态以当前配置、实际数据和本次检查为准；SQL通过不代表会计政策、库存结存或全部业务流程已经核定。
