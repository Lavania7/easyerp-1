手工录入使用说明
======================================================================


打开经营工作台，点击右上角「＋ 新建」。默认跟随当前业务模块，也可以切换到其他模块。

1. 选择业务类型。常用业务之外的记录可在「全部主录」中按名称查找。
2. 填写带 * 的必填项。可选资料放在「更多字段」内；没有掌握的内容可以留空。金额和数量不会自动补成 0，也不会自动推算收入、成本、库存结存或实际产出。
3. 关联字段可按名称或编号搜索。基础资料还不存在时，可以点旁边「新建」，保存后会回到原表单并选中该资料，已填内容会保留。基础资料点击保存后即独立保存，取消原单不会撤回这条已保存的基础资料。
4. 销售订单、采购订单、BOM 和会计凭证在同一个表单填写主录及明细。行号按表单顺序预填，数量、金额、状态仍需要明确录入。主录和全部明细作为一次事务保存，任一项失败时全部回滚。
5. 点击「保存到正式库」或「保存到演示库」。页面明确显示当前数据源；演示数据只进入独立演示库。
6. 保存后可以直接「查看保存的记录」。数据已写入现有 SQL 主录，SQLview 和查询视图会读取同一份记录。当前列表的日期、文字等筛选仍然有效；不在筛选范围内的记录可从保存成功页直接查看。

在业务详情里点击「编辑这条记录」可更正已有记录。记录编号保持不变；只提交实际改动的字段。SQLview 或其他页面在此期间修改过同一条记录时，本次保存会提示冲突，避免覆盖较新的内容。已过账凭证等既有 SQL 保护继续生效；凭证通常先保存草稿和分录，再核对、过账。


在表格中编辑
----------------------------------------------------------------------


具体列表、我的工作和主录浏览器的条数右侧提供蓝底白字、带铅笔图标的「编辑」按钮，尺寸沿用顶部「新建」按钮。点击后切换到编辑模式，表格显示蓝色边框及淡蓝色背景，右侧出现逐行「修改」入口；再次点击「完成编辑」返回视图模式。

进入编辑模式后，表格底部显示带蓝色加号的「新增条目」，没有记录的空表也可直接新增。点击后在当前表格区域展开该主录的填写表单，无需打开顶部「新建」选择器。编号可留空自动生成，也可填写自定义编号；带 * 的字段必须填写，金额和数量不会自动补零。关联字段继续从现有主录搜索选择，新记录币种沿用 CNY。保存调用同一 ``/api/entry/save`` 的 ``create`` 操作，业务记录与审计一起提交；成功后刷新当前列表，日期、搜索及其他筛选仍然有效。

新增草稿按数据源和主录单独保存，与已有记录的修改草稿分开。完成编辑、刷新、翻页或切换主录后，再次打开同一主录的「新增条目」可继续输入；切换数据源会退出编辑模式。「取消」丢弃该新增草稿，未保存的内容不会写入数据库。保存失败保留输入，同一内容丢失响应后重试沿用原请求编号，避免重复新增。来源快照及没有可写主录映射的汇总不显示新增入口。

点击某一行的「修改」会在该行下展开主录表单。「我的工作」按该事项的来源表和记录编号编辑实际主录：例如用途待核定修改用途核定记录，售后待处理修改售后事件，不把详情入口中的父订单或资金记录当成事项本身。保存后按当前筛选刷新，已不满足待办条件的事项会从列表消失。编号、自动生成字段及原记录币种不可改；其他字段按当前 SQL 字段类型、可选状态和关联记录填写。点击「保存到正式库／演示库」后直接调用现有 ``/api/entry/save``，将实际修改的字段写入所选 PostgreSQL 数据库，并在同一事务记录审计，成功后刷新查询结果。标准视图及「导入BOM与物料对应」修改其对应业务主录；关联字段和计算结果由查询重新生成。来源快照和汇总视图没有可写主录映射时，编辑按钮禁用并说明原因，原始来源保持可追溯。

「取消」丢弃当前记录未保存的输入。完成编辑、刷新、翻页或切换数据源会在本页内保留未保存输入，回到原记录再次点击「修改」可继续；关闭或重载页面前会提示存在未保存内容。草稿按数据源、表和记录编号隔离，保存仍使用开始编辑时的记录版本；发现 SQL 或其他页面已修改时保留输入并报告冲突。金额、数量和 JSON 数字保持原有精确字符串处理。

编号留空时自动生成唯一编号；也可以在更多字段里明确填写业务编号。已有编号不会被另一条新记录覆盖。重试同一次保存不会重复生成数据。


范围
----------------------------------------------------------------------


- 销售、采购与库存、生产、研发、财务、法务、分析报告都提供常用入口。
- 全部主录覆盖现有六个业务架构中的 146 张业务表。标准查询视图不直接写入，录入对应主录后由视图显示结果。
- 这一阶段提供手工新建和修改，不提供批量导入或业务记录删除。文件导入属于下一阶段。
- 当前仍为本机单用户工具；录入人身份不等同于已建立多用户登录和分级审批。


运维与验证
----------------------------------------------------------------------


原查询继续使用 ``easyerp_read`` 的只读事务；保存接口使用现有 ``easyerp_app``，只接受本机同源 JSON 请求和当前页面的保存令牌，不接受任意 SQL。密码留在服务端。

``db/app/entry_schema.sql`` 仅新增 ``erp_ops.frontend_entry_audit``，不改变原 146 张业务表。它记录请求标识、时间、SQL 角色、修改前后内容和保存结果。审计与业务记录在同一事务内写入；``easyerp_app`` 只能读取和插入该审计表，不能更新或删除审计内容。正式库和演示库各自保存审计。已有业务字段、约束、外键、核定与过账保护仍由 SQL 保证。

新环境可在数据库已就绪后运行 ``python .\tools\enable-manual-entry.py``，为正式库和已存在的独立演示库安装同样的附加审计支持。之后使用 ``bin/dashboard.exe`` 启动；代码更新后需只重启本项目的前端服务。

接口：``GET /api/entry/meta``、``GET /api/entry/options``、``GET /api/entry/record``、``POST /api/entry/save``。金额使用精确十进制字符串；不接受超出数据库小数位数的自动舍入。时间输入与回显固定使用北京时间（UTC+8），提交时显式携带+08:00换算为UTC，日期字段只保留明确填写的日期。新建记录的币种固定为CNY；编辑已有记录保留原币种，币种框不可改写。

``tests/test_manual_entry.py`` 验证实际 HTTP 和 PostgreSQL 写入、全部模块元数据、主明细事务、BOM 与凭证、精确数值、NULL、重复请求、并发、SQL 侧修改冲突和访问边界。样例只进入独立演示库，结束后清理；正式业务数据签名在测试前后必须一致。报告：``reports/manual-entry-tests.json``。


三个业务标识：短 ID 为表级前缀加至少三位大写36进制流水（例如 PO00M）；长 ID 为部门简写-主录简写-编号生成年月日-流水的十进制值（例如 PRD-PO-20261114-022）；SHA-256 是对 UTF-8 长 ID 的稳定摘要。历史记录采用迁移的编号生成日，不改业务日期。SQL 元数据在 erp_ops.business_record_ids；工作空间也保存同样三个标识。前端普通表格保留短 ID 字段，编辑与选择只露出名称；长 ID 和 SHA-256 均不展示，Agent 使用只读 /api/identity?mode=live&object=production.采购订单表&id=短ID、长ID或SHA256 查询。无部门的文件工作空间使用 WS 命名空间，不推定业务部门。


编号生成日期使用 Europe/Berlin 本地日历；事件录入和业务日期沿用既有口径。首次迁移的日期时区校正记录保存在同次迁移目录的 date-correction.json，既有数据备份和迁移原回执均保留。
