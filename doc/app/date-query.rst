
统一日期查询
======================================================================


所有模块的查询栏固定显示「起始日期」「截止日期」，两端日期都可以正常选择；主录、我的工作、待发货／待完成明细都不再隐藏起始日期或按页面修改标签。全年、季度快捷选择仍可用。顶栏公司名右侧的 v 图样已移除，公司名本身仍可打开主体信息窗。


日期口径
----------------------------------------------------------------------


筛选区间包含起始和截止当天。``date`` 字段按原日期比较，带时区时间戳先按页面固定的北京时间（Asia/Shanghai）转为日期；不使用浏览器或服务进程的本地时区替代。所属月份仍是数据库中的月首日期，普通日期选择不会自动扩展为整月。

- 销售列表及待发货明细：订单创建时间；生产列表及待完成明细：计划开始日期；财务列表：资金发生时间。
- 我的工作：资金用途沿实际资金发生时间、售后沿发生时间、工单沿计划开始日期、履约提示与整改沿期限、到货沿到货时间。日期缺失时不擅自推定日期。
- 仪表盘的指标及其明细沿用对应业务日期的起止范围；累计发货／完工等用于计算业务进展的历史事实仍累计到截止日期，不把期间外的实际履约抹掉。
- 对象浏览器及 CSV：只使用该 SQL 对象已有的日期列。``data.py`` 的 ``DATE_PRIORITY`` 按事件发生、创建、验收、到货／发货、执行／处理、交付、计算／生成、登记、检查、计划开始、生效、期限及期间等顺序选择一个字段；不存在已知名称时使用该对象第一个真实日期列。元数据和查询结果的 ``date_field`` 可核对实际字段。例如验收记录按「验收时间」，工单按「计划开始日期」，收入成本按「所属月份」，账户余额按「期间结束」，公司档案按「成立日期」。

不从文件名、记录编号、导入时间或关联对象猜测本表缺失的日期。表没有任何日期列时，日期条件不适用，文字查询与分页仍正常；已选中的日期列为 NULL 的行不属于已知日期范围，范围查询不将其计入。查询结果的 ``date_filter_applied`` 表示是否应用了日期条件。

主录详情继续按 ID 追溯完整记录。公司选择窗属于关联资料选择，不受业务列表日期范围限制，使用明确的 ``date_filter=0``；可查看、选择成立日期尚未填写的已有公司。该参数只影响已有只读查询，不改变数据库权限或原始资料。


验证
----------------------------------------------------------------------


``tests/test_date_query.py`` 及浏览器脚本验证统一标签、日期可选、视图与主录字段、分页／导出一致、北京时间换日、待办及待完成的起始边界、NULL 与无日期表、公司入口及去掉 v 图样。真实写入样例仅存在于演示库，结束清理并核对正式库签名。
