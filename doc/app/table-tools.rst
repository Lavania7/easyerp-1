表格筛选、排序与批量修改
======================

字段筛选与排序适用于 SQL 主录浏览，以及订单行、工单、资金流水三个业务列表。
保留当前正式／演示来源、日期、搜索、业务范围及负责人等条件，再按字段条件筛选。
多个字段条件为“并且”，最多八项；分页、条数和 CSV 使用同一查询条件。
排序在分页前执行，金额和数量按数据库精确数值排序，空值排最后，编号作为稳定次序。
CSV 超过 10000 条时会提示缩小筛选范围，不把截断结果当作完整导出。
计划、文件工作空间及仪表盘汇总继续使用各自界面，不在这里宣称已支持字段查询。

开启编辑后可勾选条目。“勾选本页”仅选择当前页显示的行；明确勾选的记录可跨页保留，
最多 100 条。改变来源、主录或筛选／排序条件时清空选择。复选保存的是列表查询时的原版本，
不是保存时重新读取后覆盖较新内容。

“批量修改字段”将同一主录的已选记录改为同一字段内容。界面显示目标来源、数量、字段和新内容。
主键、自动字段、币种、系统主明细归属及退役引用不可批量改；必填字段不可清空，
已过账保护和数据库原约束继续生效。不会为批量清空修改业务结构，也不提供批量过账。
金额／数量以十进制字符串传输，不经过 JavaScript 浮点数；选择“设为空值 NULL”才提交真正空值，
可选文本的空内容保留为空字符串。

整批业务修改和审计在同一事务内提交，任一记录版本冲突、不存在或违反约束时整批回滚。
失去响应时界面保留原请求标识、记录版本和内容，并提供“重试原批次”；重试不会改成新请求。
切换来源后不会把另一来源的记录或请求带到当前来源；返回同一来源与同一查询时，可继续确认原未决批次。

接口为 ``POST /api/entry/bulk``，复用既有本机、Host、Origin、JSON、大小及令牌校验。
``TableData`` 只扩展现有白名单查询，未开放任意 SQL。字段条件参数为 ``table_filters``，
排序参数为 ``table_sort``；响应中的 ``_table_tools`` 说明实际范围，``_table_version`` 仅供保存冲突检测。

验证入口为 ``tests/test_table_tools.py``；默认只执行独立校验。
``--integration --browser --out 输出目录`` 从演示快照恢复两个随机隔离库并启动临时 HTTP 端口，
测试结束只删除本次精确随机克隆，原两库只读比较非目标业务事实签名。
签名排除已批准的 010 财务档案字段变化，沿用其 ``snapshot_query(omit_changed=True)`` 口径。
