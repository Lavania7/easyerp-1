2026-11-14 括号批注实施说明
======================================


依据根目录 ``prompt.rst`` 的 32 处括号批注调整应用。原始批注文档保留。


四个层级
--------


- 企业计划：统一登记目标、部门、负责人、计划期间和关联编号。草稿发布后可以发起关联执行事项；历史生产草稿和分析规划保留来源快照。
- 工作流：一条事项包含采纳决定、实际执行、整改结果、证据和完整处理历史。支持待采纳、待执行、处理中、待复核、已完成、已取消。生产执行单独列在工作流的“生产执行”页签；领退料、完工、报废等实际事件仍在数据中心。
- 数据中心：查询已经发生的销售、采购、生产实绩、研发、财务、合同与分析事实；不列意见采纳、意见执行、整改处理等旧流程表。
- 档案馆：公司、人员、客户、供应商、产品物料、仓储地点及版本资料；会计政策、会计科目、法规、适用规则、法律文件、模型与指标定义集中维护。

另设审计入口。资金用途核定、内部划转、重复记录、往来未结和账户核对由审计处理。月度审计报告统一填写月份、核定范围、复核人、结论、未核事项和证据；发布后锁定，修订另建版本。程序不自动宣称完成月度审计，也不自动认定库存、收入、成本和业务性质。

数据与升级
----------


``db/app/workspace_schema.sql`` 仅给库存盘点增加五个可空字段，并登记升级摘要；不删除业务表、原列、原始记录或外键，不改写基础SQL生成文件。采购另由 ``db/app/purchase_intake_schema.sql`` 和 ``tools/enable-purchase-intake.py`` 增加三个可空原单字段。执行 ``tools/enable-workspace.py`` 前核对集群目录，并分别备份正式库和演示库；升级前后比较全部业务表原有事实，新增NULL不计为事实变化。

新计划、工作流和审计月报位于 ``var/workspace/live.json`` 与 ``demo.json``，不写业务SQL。保存使用同一Host/Origin/令牌边界，采用文件互斥锁、原子替换、版本冲突检查和请求幂等；处理历史保留每次前后值。备份时应同时保存整个 ``var/workspace/``，数据库dump不包含这些文件。

历史接续按明确主键和外键合并，来源快照包含原表、原ID、原字段和相关执行/处理。原状态明确结束的进入“历史归档”，未能统一解释的进入“待接续”，不擅自标记业务已审核。接续可重复执行，不覆盖已处理事项。

业务记录的关联、金额精度、并发、已过账保护、正式/演示来源和CSV空缺机制继续沿用原合同。技术明细CSV仍支持按实际关联导入；已退出录入的旧工时和流程表不接受新标准导入。
