2026-11-14 括号批注实施说明
======================================


依据根目录 ``prompt.rst`` 的 32 处括号批注调整应用。原始批注文档保留。


四个层级
--------


- 企业计划：统一登记目标、部门、负责人、计划期间和关联编号。草稿发布后可以发起关联执行事项；历史生产草稿和分析规划保留来源快照。
- 工作流：一条事项包含采纳决定、实际执行、整改结果、证据和完整处理历史。支持待采纳、待执行、处理中、待复核、已完成、已取消。生产执行单独列在工作流的“生产执行”页签；领退料、完工、报废等实际事件仍在数据中心。
- 数据中心：查询已经发生的销售、采购、生产实绩、研发、财务、合同与分析事实；不列意见采纳、意见执行、整改处理等旧流程表。
- 档案馆：公司、人员、客户、供应商、产品物料、仓储地点及版本资料；会计政策、会计科目、法规、适用规则、法律文件、模型与指标定义集中维护。

另设审计入口。资金用途核定、内部划转、重复记录、往来未结和账户核对由审计处理。月度审计报告统一填写月份、核定范围、复核人、结论、未核事项和证据；发布后锁定，修订另建版本。程序不自动宣称完成月度审计，也不自动认定库存、收入、成本和业务性质。

数据与升级
----------


``db/app/workspace_schema.sql`` 仅给库存盘点增加五个可空字段，并登记升级摘要；不删除业务表、原列、原始记录或外键，不改写基础SQL生成文件。采购另由 ``db/app/purchase_intake_schema.sql`` 和 ``tools/enable-purchase-intake.py`` 增加三个可空原单字段。执行 ``tools/enable-workspace.py`` 前核对集群目录，并分别备份正式库和演示库；升级前后比较全部业务表原有事实，新增NULL不计为事实变化。

新计划、工作流和审计月报位于 ``var/workspace/live.json`` 与 ``demo.json``，不写业务SQL。保存使用同一Host/Origin/令牌边界，采用文件互斥锁、原子替换、版本冲突检查和请求幂等；处理历史保留每次前后值。备份时应同时保存整个 ``var/workspace/``，数据库dump不包含这些文件。

历史接续按明确主键和外键合并，来源快照包含原表、原ID、原字段和相关执行/处理。原状态明确结束的进入“历史归档”，未能统一解释的进入“待接续”，不擅自标记业务已审核。接续可重复执行，不覆盖已处理事项。

业务记录的关联、金额精度、并发、已过账保护、正式/演示来源和CSV空缺机制继续沿用原合同。技术明细CSV仍支持按实际关联导入；已退出录入的旧工时和流程表不接受新标准导入。

release-1.3 内容覆盖（2026-11-15）
----------------------------------

本节及 ``version/release-1.3.md`` 覆盖本文前面的同范围旧说明。矩阵的完整数据结构、归属与引用含义及后续Agent变更方法见 `矩阵数据结构与关系规范 <matrix-data-model.rst>`__；后续数据库与关系调整按该规范执行，界面隐藏不等于删除真实结构。

- 数据库／归档的界面名称改为活动数据／静态数据，内部来源键不变。
- 部门交付独立于静态数据，按部门显示原交付记录表、交付明细表；主录及ID不复制。原部门入口不再重复出现交付分类，原二级叶子在部门交付中直接作为一级选择。
- 审计不再提供月／季／年分类按钮及type/month业务字段；统一使用起止日期、全年及Q1–Q4筛选，选部门后用普通选表菜单浏览审计主录及文件审计记录。旧真实证据和处理历史保留，旧分类字段归来源档案。
- 左上入口按“仪表盘 → 矩阵关系图 → 白板页”循环切换，不再另列映射入口；矩阵模式保留全宽蓝底白字“矩阵关系图”按钮，数据库入口与下载保持在左栏底部。矩阵模式把实际顶部部门栏及左侧功能栏变成横纵滚动坐标轴，中央平移双向同步；退出恢复原导航。没有主录或记录的格子只保留空白占位，不显示文字和边框、不可选中；同格内部引用不绘制箭头，也不计入引用方向。选中格蓝底白字、关联格蓝框、其他格变暗；已知引用使用半透明曲线箭头，按位置从上下左右四边选取起终点，同边多条连接分散落点；曲线可越过中间格子，文字显示在曲线上层。悬停或键盘聚焦关联格时强调对应连线，取消选择隐藏箭头。箭头方向为引用方到被引用主录，FK表示结构而非已发生交易；文件工作空间箭头来自明确的plan_id/links，不猜流向或部门。
- 计算器支持可编辑LaTeX、本地KaTeX预览、公式预置和十进制参数输入，实际以BigInt有理数解析求值。允许四则、括号、隐式乘法、分式及−100至100整数幂；不支持函数、根式、求和及任意脚本执行。不自动读写业务数值。精确小数继续精确，非终止结果显示四舍五入至20位小数的近似标记；保留512字符、120位输入、768位数值及32层递归限制。

迁移入口为 ``tools/migrate_supplier_items.py``，默认只预览；``--apply`` 才逐来源核对所属集群、备份、比对旧业务事实和外键并创建空供应关系表。历史工作空间在锁内备份完整原JSON并保留SHA256后，把可确定的旧报告期间转换成明确起止日期，原分类/月份保留于legacy来源字段，不改历史事件及版本。


量化计算（2026-11-15更新）
------------------------------------------------------------

左栏“计划”入口改为“量化计算”，不选择部门、不按业务日期筛选。列表仅有ID与备注，行内“计算台”保存LaTeX公式、参数及派生结果；可选“结果写入备注并保存”。不再使用顶栏浮动计算器。旧计划URL转入量化计算，旧计划及生产意向原件、plan_id引用与历史查询保留，不自动转成计算记录。

量化计算是六部门矩阵之外的独立文件空间，路径为所选来源workspace_directory下calculations/live.json或demo.json；无部门、责任人、计划状态或期限字段，不建立SQL业务表或外键。ID用CAL短号，长号为WS-CAL命名空间，版本、幂等、历史与原子写为技术元数据。每个条目1:1持有计算台；计算结果只派生于该条目显式公式与十进制参数，不引用或回写库存、订单、财务和其他业务数据。矩阵中的plans行改称“历史计划”，继续表示已有对象及原plan_id/links，不把无部门计算记录分配到任何部门格。

浏览器本地即时预览，服务端保存时用有理数重新计算，结果最多20位小数并标注近似；未知参数留空、错误不填零。新存储不改写既有工作空间文件。备份整个workspace目录包含该目录，数据库dump不包含这些文件。接口GET /api/calculations、POST /api/calculations/save沿用所选mode/db、本机/同源和令牌验证；更新携带version，重试保留request_id。Agent使用easyerp-calculations Skill及其脚本，与界面共用保存服务。

计算台分为独立的两列五区：左上备注、左下备选公式；右上LaTeX代码、右中公式预览与计算结果、右下参数值。去除数字小键盘，各区支持原生滚动或竖向扩展，窄屏改为单列。“将当前LaTeX公式保存”保存条目并把公式加入当前数据源及mode共享的备选库；条目间复用公式，参数仍单独维护。备选公式含内置模板和用户保存的公式，每项直接渲染并可点击选用。

共享公式保存在同一calculations文件顶层formulas数组，不新增列表业务字段；旧文件缺省为空，首次授权保存时按需写入。POST保存可带save_formula:true，沿用原文件锁、版本和request_id，与条目同次原子写入；空公式拒绝、相同公式去重，最多256条。GET列表及保存响应附带formulas数组；不同mode/db不共用。只保存公式不自动把结果写入备注；write_result仍由独立操作明确请求。

命名与修改共享公式（后续覆盖）
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

移除全部内置备选公式，仅展示用户保存的共享定义。LaTeX代码框下方一行提供可选公式名称与“将当前LaTeX公式保存”；结果标签为“计算结果”。参数名右侧同行显示已填写的含义，未填写不显示占位。名称及参数含义属于公式／计算台元数据，不新增ID、备注以外的计算条目列表业务字段，也不改变六部门SQL矩阵或外键。

formulas由字符串数组兼容为对象数组，包含内部id、version、name、expression、parameter_notes、history；旧值按内容生成稳定内部ID，读操作不写文件。完整定义去重，用户名称保留原文。新建条目左侧白色“修改已保存的公式”展开共享公式编辑区，支持改名称、公式与参数含义。POST /api/calculations/formulas/save独立修改定义，带request_id/id/version；沿用同源、令牌、文件锁、原子写、幂等、版本冲突和历史。旧条目仍持有其独立计算台快照，再选用模板时才载入新定义。

计算条目board增加formula_name和parameter_notes；notes仅保存识别参数的非空含义。名称最多120字、含义每项300字、公式512字；不同mode/db隔离及计算口径不变。Agent Skill同步增加formula-edit操作。
